# app/: the Swift menu bar app

Up: [../AGENTS.md](../AGENTS.md)
Verified: 2026-11-09

A SwiftPM executable (`Package.swift`, macOS 13+: SwiftUI APIs new in macOS 14, such as the two-argument `onChange` or `Text.foregroundStyle`, need an `#available` check or the older form) that links the Rust static library that `scripts/build.sh` stages in `core/target/lib` through the `CPusmogoCore` module map. Build it with `../scripts/build.sh`, never with `swift build` alone: the script builds the Rust core first and assembles `build/Pusmogo.app`.

## Map

| File | Role |
|---|---|
| `PusmogoApp.swift` | App entry and the menu bar icon (no Dock icon) |
| `SingleInstance.swift` | One running copy: a copy launched while an older one runs asks it to open its panel (distributed notification) and quits; the one-shot test hooks (`PUSMOGO_SELFTEST_WAV`, `PUSMOGO_INSERT_TEST`, `PUSMOGO_MIC_TEST`, `PUSMOGO_PREVIEW_HOVER`, `PUSMOGO_APPLICATIONS_DIR`) are exempt |
| `AppMover.swift` | Move to Applications: a launch from outside /Applications and ~/Applications (Downloads, a disk image, a build folder) offers once to copy itself there, opens the copy after quitting, and removes the old copy only from Downloads (to the Trash). Skipped under any other `PUSMOGO_` hook; "Don't ask again" saves `moveToApplicationsDeclined` |
| `AppState.swift` | Dictation state machine, language choice, `PUSMOGO_DEMO` cycle, `PUSMOGO_SELFTEST_WAV` self-test |
| `KeyboardTap.swift` | Global hotkeys: turns CGEvents into inputs for `KeyMachine` (`Sources/PusmogoKeys/`, pure Swift, tested by `swift test` in `Tests/PusmogoKeysTests/`), which decides hold, double/triple tap fn, fn + ⇧, Esc, and the optional second push-to-talk key (Right ⌥/⌘/⌃, Settings). Change a gesture there and add a test. `PUSMOGO_DEBUG_KEYS=1` logs presses and every intent |
| `AudioRecorder.swift` | Microphone capture, 16 kHz mono for the core; picks the input (`MicDevice.automatic`: never a Bluetooth default when a built-in or wired one exists, `PusmogoKeys/MicPick.swift`), never keeps a Bluetooth one running, and captures through `InputUnit.swift` (one HAL input unit, not `AVAudioEngine`: that also opens the default devices and puts a connected headset in call mode). Check with `PUSMOGO_MIC_TEST=<s>`, plus `PUSMOGO_MIC_TEST_HOLD=<s>` to see what the app still holds afterwards; `takeNew()` hands over audio since the last call for streaming. Its `SampleBuffer` keeps the whole dictation for the first 5 min (a language swap transcribes it all again), then drops audio the session already took, so a long hands-free dictation stays flat in memory; a swap after that finishes in the session's language. The self-test streams through a `SampleBuffer` too; `PUSMOGO_RECORDER_KEEP_SECS=<s>` changes the limit for tests |
| `Core.swift` | Thin Swift wrapper over the C ABI in `../core/include/pusmogo.h`, including the streaming session (fed once a second while recording), the profile (history written per dictation, dictionary re-applied after every engine load) and context hints (the focused field's text before the caret, read on key down through `FocusedText` in `Paster.swift`, cleared after the dictation; never logged or stored), and the test-set recording calls (`Core.testsetStatus`, `saveTestTake`, `writeTestsetConsent`; takes go under `testset/` beside the models folder, `PUSMOGO_TESTSET_DIR` overrides it) |
| `Core.swift` → `Core.SpeechModel` | The two speech models (turbo, large-v3), their files and pinned sizes, and the per-language pick from the core (`models.rs`). UserDefaults `model.hu` / `model.en`: 0 automatic, 1 fast, 2 most accurate (Settings writes them through `AppState.setModel`, which reloads at once when idle) (pass `-model.hu 1` after the executable path in tests). `PUSMOGO_FAKE_RAM_GB=8` acts as an 8 GB Mac. A language swap loads the other language's model (in the background when idle, else on the next key down); streaming steps every 2 s with large-v3, 1 s with turbo |
| `Paster.swift` | Inserts text into the focused app: Accessibility direct insert (read back to confirm), else lazy pasteboard + ⌘V (the focused field is read back; clipboard restored only when the text is seen to land, left holding the text when the field is unreadable), else a "copied" notice |
| `EditWatcher.swift` | Learning from edits (C10): after a verified insert, reads the same field once a second (30 s, `PUSMOGO_EDIT_WATCH_SECS`; 0 = off) and, once a changed text holds still for two reads, asks the core (`Core.learnedCorrection`) whether the user replaced a dictated word; a match not already in the dictionary becomes `AppState.editSuggestion`, shown for 12 s above the sound bar as an "Add to dictionary" offer (`DictionaryOffer` in `FlowBar.swift`; accepting saves it through `addDictionaryEntry`). Every fix is first recorded through `Core.noteCorrection`; the second identical fix is added at once and the offer shows it with Undo instead (`Suggestion.learned`; preview: `PUSMOGO_PREVIEW_HOVER=offer|learned`). Words are logged only with `PUSMOGO_DEBUG_EDITS=1` |
| `MediaPause.swift` | Media pause (C8, Settings switch, on by default): on a real dictation (after the same 0.18 s as the start sound, so taps and fn + ⇧ don't count) it asks Core Audio which other processes are playing; only then it sends the system pause command (MediaRemote, looked up at run time), and on release it sends play only if one of those processes went quiet. `PUSMOGO_DEBUG_MEDIA=1` logs each decision; the self-test runs it too. Test only against a player you start yourself |
| `FlowBar.swift` | The sound bar: non-activating panel at the bottom of the screen; the idle bar grows under the mouse into a pill with a microphone button (hands-free dictation) |
| `PanelView.swift` | The panel under the menu bar icon: Home, History (search in an `NSSearchField`: Esc clears a typed search, then closes the panel; delete, clear all on the profile; a row can be typed again into the app that was in front before the panel, `AppState.insertAgain`), Dictionary (two parts, Words and Snippets. Words: editor on the profile; a filter field above lists of more than 15 entries; a row's pencil loads it into the add fields, and Save replaces that row. Snippets: trigger + text editor over the core's snippets, newest first; `PUSMOGO_DICTIONARY_SECTION=snippets` opens that part), Settings (incl. history retention, applied at once and after every dictation; export/import of the whole profile through save/open panels; "AI apps": two switches, off by default, writing the profile settings `mcp.shareHistory` / `mcp.shareDictionary` that let the local `pusmogo-mcp` read history, dictionary and snippets; `PUSMOGO_SELFTEST_SHARE=history,dictionary` turns them on in a self-test's profile) |
| `McpClientsView.swift` | Settings → AI apps, under the switches: one row per AI app (Claude Desktop, Claude Code, Cursor) that registers the bundled `Contents/MacOS/pusmogo-mcp` in its MCP config through the core (`Core.mcpInstall` etc., `mcp_config.rs`). Add shows the diff and saves only on Save (backup first); Undo removes our entry; an unreadable config is shown and never touched; a copy outside an Applications folder says the config will point at it. **Tests always set `PUSMOGO_MCP_HOME=<scratch folder>`** (never the real home); `PUSMOGO_PREVIEW_MCP_DIFF=<client id>` opens that client's diff for a screenshot; presses log `mcp: install <client> <code>` |
| `StyleTab.swift` | The Style tab: a writing style per app category (UserDefaults `style.<0-3>`; code, category 4, is fixed and shows only its example) with an example rendered live by the core (`Core.applyStyle`), and the user's app → category mapping (`styleOverrides`; "Add <app>" maps the app that was in front before the panel) |
| `InsightsTab.swift` | The Insights tab (chart icon; Settings is the gear): numbers from `Core.insights` (core `insights.rs`, local time zone), read each time the tab opens; the core's title key gets its HU/EN name and line here. Screenshot it within ~2 s of a self-test launch with `PUSMOGO_PANEL=insights` and a profile seeded with `sqlite3`: the self-test's panel window goes away after a few seconds |
| `Onboarding.swift` | First-run window (permissions, model download, try it) |
| `TestSetWindow.swift` | Test-set recording mode: speaker pseudonym, consent level (writes `consent.txt`), then one script line at a time (Space or Record starts and stops a take, whispered takes are marked), saved by the core under `testset/<speaker>/`; its own `AudioRecorder`, nothing typed or uploaded. `PUSMOGO_TESTSET=<speaker>` opens it at launch (no key tap, next to an installed copy, quits when closed); `PUSMOGO_TESTSET_WAV=<clip>` records that clip instead of the microphone and keeps focus where it is; always pair with a scratch `PUSMOGO_TESTSET_DIR`. Settings → Tesztfelvétel → Megnyitás opens it in a running copy (closing it then does not quit). While the window is in front, the dictation keys record takes instead of dictating (`TestSetWindow.route` in `AppState.handle`: hold records, release saves, a tap or Esc discards); check with `PUSMOGO_SELFTEST_KEYS=1` + `-altKey rightCommand` and posted Right ⌘ presses |
| `Updater.swift` | App updates through Sparkle (feed and public key in `Info.plist`, framework trimmed and signed by `scripts/build.sh`): off under any `PUSMOGO_` test hook except `PUSMOGO_FEED_URL`, which reads another list; Settings shows the switch and "Keresés most". Releases: `scripts/release.sh` |
| `ModelStore.swift` | Model location and download, one store per model (`AppState.models` is turbo, the first download that onboarding, Home and Settings show; `AppState.accurateModel` is large-v3, fetched quietly once turbo is ready and the current language wants it, retried at the next launch or swap; test runs fetch it only from `PUSMOGO_LARGE_MODEL_URL`): pinned URL, SHA-256 checked before install; resume data is kept in `<model>.resume` so Retry or the next launch continues a dropped or quit download; a model file of the wrong size counts as damaged (not loaded, dictation refused, removed on Download) |
| `DesignSystem.swift` | `DS` tokens: colours, radii, spacing, fonts, motion |
| `Sounds.swift` | UI sounds, synthesised at launch (no audio assets) |
| `AppIcon.icns`, `AppIcon.icon/` | App icon (the mark in `../docs/assets/logo.svg`: fused bars with eyes, on the accent) and its macOS 26 layers, generated by `../scripts/make-icon.swift`; never edit by hand |
| `Timings.swift` | Per-dictation stage timings, logged to `~/Library/Logs/Pusmogo/timings.jsonl` (cut to the newest 1000 lines past 256 KB, `PusmogoKeys/LogTrim.swift`); test launches point it elsewhere with `PUSMOGO_TIMINGS_LOG=<path>` so they do not mix with an installed copy's lines |

## Rules

- **Design tokens only.** Colours, radii, spacing, fonts and animations come from `DS` in `DesignSystem.swift`. One accent colour (`DS.Color.accent`). Add a token there rather than a literal in a view.
- **Copy:** UI text is Hungarian, informal *te*, no exclamation marks, no em dashes. The Hungarian text is the localisation key: English lives in `Resources/en.lproj/Localizable.strings` (and `InfoPlist.strings` for the microphone prompt), copied into the bundle by `../scripts/build.sh`. Literals passed to `Text`/`.help` are looked up automatically; a `String` built in code needs `String(localized:)`. `../scripts/check-strings.py` fails on a literal with no English key (`--verbose` also lists keys it cannot match to a literal, such as text passed through custom views). Check English with `-AppleLanguages '(en)'` after the executable path.
- **Windows:** none except onboarding, the test-set recording window and the panel window that ⌃⌥P opens (`PanelWindow`, for when a full menu bar hides the icon behind the notch; Esc closes it). The hidden-icon check runs 3 s after launch, on display changes and every 3 min (`PUSMOGO_ICON_CHECK_SECONDS`); its bar notice shows once per launch, and while the icon stays hidden the hovered idle bar adds a panel button and Home shows how to ⌘-drag icons off the menu bar (`AppState.menuIconHidden`). The sound bar never takes focus.
- **Logic** that can be tested without a GUI belongs in `../core`, not here.
- The Swift type checker gives up on long inline numeric expressions inside SwiftUI builders; move them into small helper functions.

## Verify UI changes with a screenshot

Reading the view code is not verification. Use the `screenshot-ui` skill ([../.agents/skills/screenshot-ui/SKILL.md](../.agents/skills/screenshot-ui/SKILL.md)):

- `PUSMOGO_DEMO=1` cycles the sound bar through all its states.
- `PUSMOGO_PREVIEW_HOVER=1` shows the idle bar as if the mouse were over it (the grown pill with the microphone button and its tooltip); `track` follows the real mouse instead. Either way the app installs no key tap, may run next to another copy, and quits after `PUSMOGO_PREVIEW_SECS` (default 12). `PUSMOGO_NOTETAKER=1` adds the planned notetaker button, disabled. `PUSMOGO_PREVIEW_HOVER_BUTTON=dictate|notes|panel` shows that button's tooltip. Hover tracking reads mouse moves only (no permission); the pill takes clicks only while the mouse is over it, collapses 0.6 s after it leaves, and its microphone button starts a hands-free dictation without taking focus.
- Move to Applications: never test against the real /Applications. `PUSMOGO_APPLICATIONS_DIR=<scratch dir>` is then the only Applications folder (one-shot run, logs `move:` lines, the relaunched copy logs where it runs and quits), `PUSMOGO_DOWNLOADS_DIR=<dir>` counts as Downloads, `PUSMOGO_MOVE_ANSWER=move|later` answers the offer, `preview` shows it without taking focus for a window-id screenshot.
- `PUSMOGO_ONBOARDING_CYCLE=<seconds>` steps through onboarding; launch with `-onboarded NO` after the executable path to show it (a launch argument, so the saved flag, shared with any installed copy, stays as it is). Like `PUSMOGO_DEMO`, it is not a one-shot hook: with another copy running it hands over and quits.
- `PUSMOGO_ONBOARDING_STEP=<0-6>` opens onboarding at one step (3 is try it). Combined with the self-test below (`PUSMOGO_SELFTEST_INSERT=1`), the clip is dictated into the try-it field and the window stays up 4 s for a screenshot.
- `PUSMOGO_PANEL=<home|history|dictionary|style|insights|settings>` opens the menu bar panel on that tab in an ordinary window (the real popover: next item). Pair it with `PUSMOGO_PROFILE=/tmp/x.sqlite`; its fields and buttons can be driven through Accessibility (`AXValue`, `AXPress`) without stray keystrokes. Setting the History search field's `AXValue` does not run the search (the change never reaches the field's delegate); use `PUSMOGO_HISTORY_QUERY=<text>` to open History with that search typed. Dictionary shows a filter field (heard or written text, ignoring case and accents) once it holds more than 15 entries; `PUSMOGO_DICTIONARY_QUERY=<text>` opens it with that filter typed.
- The real popover: `PUSMOGO_PANEL` also sets its first tab. Open it by sending `AXPress` to the app's status item (`AXExtrasMenuBar` → first child) and capture it by window id (layer 101, 360 wide). AX presses and synthetic clicks inside it close it, so `PUSMOGO_PANEL_CYCLE=<seconds>` steps through the tabs instead (logs `panel: tab <name>`); the scripted switch can still close it after a few steps. Lists inside the panel use `FittedScroll` (a bare `ScrollView` has no ideal height and collapses in the popover), and `WindowHeightFitter` resizes the window to the panel, because the popover never shrinks by itself.
- `PUSMOGO_PREVIEW_HIDDEN_ICON=1` acts as if the icon were hidden: the "menu bar icon hidden, ⌃⌥P" notice 3 s after launch, the hover bar's panel button and Home's help card (also in a `PUSMOGO_PANEL=home` self-test window) (`StatusItemVisibility` in `PanelView.swift` logs `menu bar: icon window <frame>` every launch). To hide it for real without touching settings, run a scratch process that adds about ten 70-point `NSStatusItem`s first; Pusmogo's icon then sits off screen and the real check fires.
- `PUSMOGO_PREVIEW_DENIED=1` (or `mic`, `ax` for only that one) shows microphone and Accessibility as not granted (no prompt, real permissions untouched), so the denied state of the permissions step (`PUSMOGO_ONBOARDING_STEP=1`) and the menu can be screenshotted on a Mac that already granted them. Onboarding only opens with `-onboarded NO` (or with `PUSMOGO_ONBOARDING_STEP` under the self-test).
- `PUSMOGO_PREVIEW_BLUETOOTH=1` treats the microphone in use as a Bluetooth one, so the Settings hint under the microphone picker can be screenshotted without a headset.
- `PUSMOGO_PREVIEW_MIC_NAME=<name>` adds a fake input (uid `preview`) to the Settings microphone list; launch with `-micUID preview` after the executable path to show it selected without saving the choice, so a long device name can be screenshotted.
- `PUSMOGO_TRANSFER_DIR=<dir or file>` opens the Settings export/import panels there (a file is preselected in the open panel), so they can be finished through Accessibility (`AXPress` on Save/Replace/Open) with a scratch `PUSMOGO_PROFILE`.
- `PUSMOGO_PREVIEW_MODEL=missing|downloading|failed|offline|damaged|diskfull` shows that model state in onboarding step 3, Home and Settings; `download()` is a no-op then, so nothing is fetched and the real model file is untouched. `PUSMOGO_PREVIEW_LARGE_MODEL=<same values>` does the same for the background large-v3 download, shown as one quiet line on Home and in Settings while it runs or after it failed (Hungarian only, once turbo is ready).
- `PUSMOGO_MODELS_DIR=<empty dir>` makes the app look for the model there, so the real no-model path (status chip "Nincs modell", dictation refused with a bar notice instead of stub text) can be checked without moving the real file. Add `PUSMOGO_PREVIEW_MODEL=missing` so the download that notice starts stays inert, and keep onboarding out of it (it would start a real download into that folder).
- `PUSMOGO_MODEL_URL=<url>` downloads the model from elsewhere (e.g. a local `python3 -m http.server`); the pinned SHA-256 in `ModelStore.modelSHA256` still applies, so a wrong file ends in "The downloaded model is damaged". Pair it with a scratch `PUSMOGO_MODELS_DIR`. A download that receives no bytes for 20 s stops and offers Retry (`PUSMOGO_DOWNLOAD_STALL_SECS` changes the limit).

Look at the PNG, then kill every Pusmogo process you started.

## Exercise the dictation path without a key press

`PUSMOGO_SELFTEST_WAV=<16 kHz mono WAV>` plays the clip through the app's real path (prepare on key down, transcribe, timings), logs the text instead of typing it, and quits. Without `PUSMOGO_PROFILE` it uses an empty temporary profile, removed on exit, so test runs never land in the user's History or use their dictionary. The clip is fed to the streaming session in real time, as the microphone would; `PUSMOGO_STREAM=0` turns streaming off for an A/B run. `PUSMOGO_SELFTEST_RUNS`, `PUSMOGO_SELFTEST_GAP` and `PUSMOGO_SELFTEST_DELAY` (seconds) repeat it; with `PUSMOGO_IDLE_UNLOAD=5` and a gap above 5 every run after the first reloads the model. `PUSMOGO_SELFTEST_SWAP=<s>` presses fn + ⇧ that many seconds into the clip, so the whole clip is transcribed again in the other language; it saves the new language like a real swap, so start with `-language en|hu` and run `defaults delete ai.vatson.pusmogo language` afterwards. Like a key press, it reads the focused field's text before the caret as context hints (`PUSMOGO_SELFTEST_CONTEXT=0` skips that; the Settings switch "Use surrounding text", UserDefaults `contextHints`, turns hints off for real dictations too, and `PUSMOGO_CONTEXT_HINTS=0|1` overrides it, logging `context hints off`). Spoken self-corrections ("háromkor, nem, négykor" → "négykor") are dropped unless the Settings switch "Catch self-corrections" (UserDefaults `selfCorrections`, on by default) is off; `PUSMOGO_SELF_CORRECTIONS=0|1` overrides it, logging `self-corrections off`. For context hints, `../scripts/insert-probe.swift native <s> "<text>"` gives the self-test a field with known text. `PUSMOGO_SELFTEST_INSERT=1` also types the text into the focused app, so only use it with a known target window in front. Each dictation is styled for the app in front at key down (core `style.rs`: category from the bundle id, a browser's window title, or UserDefaults `styleOverrides` lines `bundle.id\tcategory`; style per category in `style.<0-3>`, 0 formal, 1 casual, 2 very casual, personal messages casual by default; logs `style: category N, style M`). `PUSMOGO_STYLE_BUNDLE=<bundle id>` stands in for the app in front and `PUSMOGO_STYLE_TITLE=<title>` for its window title (in the code category the title goes into the context hints, so identifiers and file names it shows are spelt as on screen), and launch arguments such as `-style.1 2` test a style without saving it. A dictation whose whole cleaned text is a snippet trigger types the saved text verbatim instead (no style pass; logs `snippet: trigger matched`); `PUSMOGO_SELFTEST_SNIPPET=<trigger><TAB><text>` (`\n` for a line break) saves one into the self-test's profile first. The Snippets part also exports and imports them as a JSON list of `{"trigger", "text"}` (import adds; a trigger already saved gets the file's text; a file that is not such a list changes nothing); `PUSMOGO_SELFTEST_SNIPPETS_IMPORT=<json>` and `PUSMOGO_SELFTEST_SNIPPETS_EXPORT=<json>` run both in a self-test (logs `snippets: import N of M`, `snippets: export N done`).

Every dictation, the self-test's too, is written to the profile (`~/Library/Application Support/Pusmogo/profile.sqlite`: history, dictionary, settings). Point tests at a scratch file with `PUSMOGO_PROFILE=/tmp/x.sqlite` and inspect it with `sqlite3`.

`PUSMOGO_MIC_TEST=<seconds>` records from the microphone chosen in Settings (UserDefaults `micUID`, empty means the system default), logs every input, the device and format used, the seconds of audio received, its RMS, how long after start the first sample was captured and how much digital silence it began with, and quits. It checks the capture path without a held key; it does not transcribe. Every dictation logs the same start delay as `micStartMs` in `timings.jsonl`. `../scripts/mic-path-check.swift` checks the format conversion offline (`../docs/bench/mic-02.md`).

The Settings switch "Keep the last 20 dictations" (UserDefaults `keepDebugAudio`, takes effect at once; its Folder button opens the folder) or `PUSMOGO_KEEP_AUDIO=1` (forces it on; `=0` forces it off) keeps the newest 20 dictations in `~/Library/Application Support/Pusmogo/debug/`: the exact 16 kHz audio the engine received (`<stamp>.wav`) and its raw and cleaned text, prompt and hint words (`<stamp>.json`; core `debug.rs`). Off by default, never uploaded. `PUSMOGO_DEBUG_DIR=<dir>` writes the record to another folder. A self-test (`PUSMOGO_SELFTEST_WAV`) never records unless `PUSMOGO_KEEP_AUDIO=1` is set, whatever the switch says; point it at a scratch folder with `PUSMOGO_DEBUG_DIR`. **Every other test launch that dictates (held-key or loopback runs, demo and panel shots) sets `PUSMOGO_KEEP_AUDIO=0`**: the defaults domain is shared with any installed copy, so the switch may be on, and test clips would push the user's own dictations out of the 20-slot record. Never read, copy or delete files in the real `debug/` folder; it holds the user's voice. Replay a kept dictation with `PUSMOGO_SELFTEST_WAV=<stamp>.wav` or the bench.

`PUSMOGO_INSERT_TEST=<text>` inserts the text into the focused app after `PUSMOGO_INSERT_DELAY` seconds (default 2), logs `insert-test: direct|pasted|pasted:unverified|copied:<reason>`, shows the same notice as a real dictation and quits without loading the model. `PUSMOGO_INSERT_MODE=paste` forces the pasteboard path. `PUSMOGO_INSERT_LINGER=<s>` keeps the app up after the insert, so an edit made to the probe's field through Accessibility (`kAXValue`) shows up as `edit-watch: correction found` (with `PUSMOGO_DEBUG_EDITS=1`) and the offer appears on the bar; with `PUSMOGO_PROFILE=<scratch file>` the profile is opened too, so pressing the offer's button (`AXPress`) saves a dictionary row. `../scripts/insert-probe.swift` is a target window you control (native, one-line, web textarea, web `<input>`, no Edit menu, no field) that prints what landed; see `../docs/bench/insert-01.md`. Read the field back through Accessibility, not AppleScript: AppleScript to another app raises a permission prompt.
